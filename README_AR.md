# PharmaStock v0.5 — ثلاثة حسابات وتخزين سحابي فقط

## التغييرات
- ثلاثة حسابات مندوبين مستقلة ومتساوية الصلاحيات، يتم إنشاؤها في Supabase Authentication (لا توجد حسابات فعلية قبل الإنشاء).
- إلغاء IndexedDB وطابور الفواتير المحلي والعمل دون اتصال.
- الأدوية والكميات والفواتير محفوظة في Supabase فقط. لا تُحفظ نسخ بيانات المخزون على الهاتف.
- تعطيل استمرار جلسة تسجيل الدخول في localStorage (`persistSession: false`): قد تحتاج إلى تسجيل الدخول مجدداً عند إعادة تحميل الصفحة.
- عند انقطاع الإنترنت تتوقف إضافة الأدوية والاستلام والبيع، ولا توجد مزامنة مؤجلة.
- يستمر ظهور اسم المندوب في إدخال الأدوية والبيع والسجل، مع مخزن مشترك واحد.

## إعداد جديد
1. أنشئ مشروع Supabase جديداً.
2. نفّذ `supabase/schema.sql` ثم `supabase/representatives_migration.sql` من SQL Editor بهذا الترتيب.
3. افتح Authentication > Users وأنشئ ثلاثة مستخدمين ببريد مختلف لكل شخص وكلمة مرور قوية لكل حساب. تأكد من إعداد تأكيد البريد الإلكتروني.
4. افتح `supabase/activate_three_accounts.sql` واستبدل عناوين `rep1@example.com` و`rep2@example.com` و`rep3@example.com` بعناوين الحسابات الثلاثة، وعدّل أسماء المندوبين، ثم نفّذ الملف في SQL Editor. تحقق من ظهور ثلاثة صفوف `active=true`.
5. أنشئ ملف `.env.local` محلياً بالقيم العامة `VITE_SUPABASE_URL` و`VITE_SUPABASE_ANON_KEY` (لا ترفع هذا الملف إلى GitHub).
6. شغّل `npm install` ثم `npm run dev` للتجربة، أو ارفع ملفات المشروع إلى GitHub، واضبط GitHub Actions Variables بالاسمين نفسيهما، ثم Settings > Pages > GitHub Actions.

## ملاحظات أمنية وتشغيلية
- لا تضع كلمات مرور المندوبين في GitHub أو في SQL أو في المحادثة.
- لا تستخدم مفتاح `service_role` داخل تطبيق الويب.
- لا يمكن منع المتصفح من تخزين ملفات الموقع المؤقتة أو آثار الشبكة بشكل مطلق، لكن التطبيق لا يخزن بيانات المخزون والفواتير في تخزين الهاتف المحلي.
- عند ضعف الشبكة، قد تنجح عملية البيع على الخادم رغم فشل استلام الرد. راجع السجل قبل إعادة المحاولة لتجنب بيع مكرر. يلزم تحسين آلية إعادة المحاولة قبل الإنتاج.
- لا يوجد حد تقني مفروض بثلاثة مستخدمين: الملف يفعّل ثلاثة حسابات مبدئياً، ويمكن إضافة غيرهم لاحقاً.
- هذه نسخة أولية غير مختبرة مع مشروع Supabase حقيقي؛ لا تعتمدها للمبيعات الفعلية قبل الاختبار والنسخ الاحتياطي.
